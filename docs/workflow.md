# 開発ワークフロー（お試し運用）

## 履歴管理

- 変更は小さく刻んでコミットする（例：「ダイヤル錠の判定を修正」「ヒント文を追加」）
- 壊れたら任意のコミットまで戻せることが目的
- ゲーム本体は `index.html`（単一ファイル）、仕様は `docs/` に置く

## タスク管理

- やること・バグ・思いつきは GitHub Issues に1件ずつ起票
- 優先度はラベルではなく本文と順番でゆるく管理（個人開発向けの軽量運用）

## 分担

| 役割 | 担当 |
|---|---|
| 仕様決定・面白さの最終判断・公開の承認 | daisuke774 |
| 実装・動作確認（通しプレイ検証）・ドキュメント整備 | Muse |

## 変更の流れ

1. Issueでやることを決める
2. Museが実装し、通しプレイで詰みがないか検証
3. コミットして履歴に残す
4. 公開（スペースの共有リンク）はdaisuke774の承認後に行う
